## Dotfiles

### `.bashrc`
- Sources `/eecs/local/share/bashrc.common` when present.
- Sets:
  - `TERM=xterm-256color`
  - `EDITOR=nvim`
  - `VISUAL=nvim`
- Enables Vim-style shell editing (`set -o vi`).
- Defines prompt as `\u@\h: \w\$ `.
- Includes a GCC path line intended to add `/eecs/local/pkg/gcc-12.3.0/bin`.

### `Microsoft.PowerShell_profile.ps1`
- Adds alias: `make -> mingw32-make.exe`.
- Sets PSReadLine to Vim mode (`Set-PSReadlineOption -EditMode vi`).

### `wezterm.lua`
- Auto-reloads config changes.
- Uses color scheme: `Gruvbox dark, hard (base16)`.
- Starts in PowerShell with default cwd `C:\dev`.
- Keeps close confirmation prompt enabled.
- Sets window padding.
- Adds a Neovim-like pane control key table triggered by `ALT+SHIFT+w`:
  - `v`: horizontal split
  - `s`: vertical split
  - `h/j/k/l`: move focus left/down/up/right

## Neovim config

### `neovim/init.lua`
- Entrypoint that loads `lua/ali/init.lua`.

### `neovim/lua/ali/init.lua`
- Loads:
  - `ali.config.lazy`
  - `ali.config.options`

### `neovim/lua/ali/config/lazy.lua`
- Bootstraps `lazy.nvim` if missing.
- Sets:
  - `mapleader = " "`
  - `maplocalleader = "\\"`
- Loads plugins from `ali.plugins`.
- Enables lazy.nvim update checker.

### `neovim/lua/ali/config/options.lua`
- Core options:
  - Tabs/spaces: 2 spaces (`tabstop`, `shiftwidth`, `softtabstop`, `expandtab`)
  - Incremental search enabled
  - `signcolumn = yes`
  - `netrw_keepdir = 0`
- Windows shell integration:
  - Uses `powershell.exe` for `:!` and shell commands.
- Keymaps:
  - Center cursor after `<C-d>` / `<C-u>`
  - Telescope:
    - `<leader>ff` find files
    - `<leader>fg` live grep
    - `<leader>fb` buffers
    - `<leader>fh` help tags
  - LSP (on `LspAttach`):
    - `K` hover
    - `gd`, `gD`, `gi`, `go`, `gr`, `gs`
    - `<F2>` rename
    - `<F3>` format
    - `<F4>` code action
- Completion:
  - Configures `nvim-cmp` with `cmp-nvim-lsp` source.

### `neovim/lua/ali/plugins/gruvbox.lua`
- Installs/configures `ellisonleao/gruvbox.nvim`.
- Applies `colorscheme gruvbox`.

### `neovim/lua/ali/plugins/line-numbers.lua`
- Installs `shrynx/line-numbers.nvim`.
- Enables dual-mode relative/absolute line numbers (`mode = "both"`).

### `neovim/lua/ali/plugins/lsp.lua`
- Installs/configures:
  - `mason.nvim`
  - `mason-lspconfig.nvim`
  - `nvim-lspconfig`

- Ensures these servers are installed:

  - `clangd`

- Applies shared completion capabilities to all configured servers.

### `neovim/lua/ali/plugins/lualine.lua`

## Omarchy config

Mirror of `~/.config/omarchy` on the Omarchy (Arch + Hyprland) machine. Runtime
state, `.git` directories, timestamped `.bak.*` backups, all `.sample`
templates, and the third-party `io.github.kristoferlund.webcam` plugin clone are
excluded.

### `omarchy/shell.json`
- Omarchy shell (Quickshell) settings:
  - Idle: screensaver at 150s, lock at 300s.
  - Top bar, transparent, centered on `omarchy.clock` (`dddd HH:mm`, alt `d MMMM 'W'ww yyyy`).
  - Left: `omarchy.menu`, `mushroom.workspaces`.
  - Center: `omarchy.indicators`, `omarchy.clock`, `omarchy.elsewhen` (Toronto,
    London, Dubai, Tokyo, Los Angeles), `omarchy.weather`, `omarchy.system-update`.
  - Right: keyboard layout, tray, webcam, tailscale, agents, bluetooth, network,
    audio, monitor, power.
  - Bar plugin: `mushroom.bar`.
  - Plugins: `mushroom.dock`, `mushroom.dashboard`, `mushroom.notifications`.
  - Dock (`mushroom.dock`, a clone of `omarchy.dock`): bottom edge, auto-hide
    off, pinned apps chromium, wezterm, Nautilus, obsidian, signal, Discord,
    OBS, kdenlive, mpv, Moonlight.
  - Disabled: `omarchy.notifications` and the dock source `omarchy.dock`
    (replaced by the clone); clone sources restorable: `mushroom.notifications`,
    `mushroom.dock`.

### `omarchy/shell.toml`
- Sets shell font `base-size = 11`.

### `omarchy/themes/mushroom-grove/`
Custom dark theme:
- `colors.toml`: warm brown/cream palette, accent `#e86f5a`.
- `shell.toml`: shell overrides for the theme.
- `hyprland.lua`: Hyprland appearance overrides.
- `backgrounds/enchanted-grove.png`: wallpaper.

### `omarchy/plugins/mushroom.*`
User-authored Quickshell plugins:
- `mushroom.bar`: full bar implementation with widget manifests (active window,
  indicators, keyboard layout, microphone, spacer, system update, tray,
  workspaces) and indicator components (dictation, DND, night light, reminder,
  screen recording, stay awake).
- `mushroom.dashboard`: dashboard window with model, icons, and shader
  (`vortex.frag`).
- `mushroom.dock`: clone of the first-party `omarchy.dock` (marked
  `omarchy.clonedFrom`, so the built-in is disabled and built-in IPC ids route
  here) with the mushroom-grove look and on-demand behavior layered on.
- `mushroom.notifications`: notification service and card components.
- `mushroom.workspaces`: workspace widget.

### Dock (`mushroom.dock`)

Built on the stock dock, so it keeps the stock model:
- Shows on floating workspaces (and can be called up anywhere), respects
  fullscreen, supports drag reorder, external drag-in from the app grid,
  context menus (position, auto-hide, new window, keep/remove, quit), and
  launch pulses.
- Pins live in `shell.json` `.dock.pinned` and are written through
  `omarchy dock pin/unpin/pinned`; there is no plugin-local `pinned.json`.

Mushroom styling and behavior:
- Translucent theme-tinted pill with rounded shadow; mushroom launcher disc;
  circular app discs with focus bloom; instance-count badges; running
  indicators.
- Proximity magnification: discs grow toward the pointer and neighbours make
  room, computed against the unmagnified slot grid.
- One shared hover label (`Name · N windows`).
- Tucked off the edge by default away from floating workspaces; reveals on a
  `Super` tap, at the dock edge, via IPC, or pins open. While tucked, only the
  hair-thin edge strip takes input, so the desktop stays click-through.

Launcher disc: left click opens the Omarchy menu, right click a terminal,
middle click the stock app grid, `Shift`+left the stock dock settings menu.

IPC:
- `omarchy-shell mushroom-dock peek|dismiss|toggle|show|hide|cycle <1|-1>|pin <id>|apps|refresh|ping`
- `omarchy-shell omarchy.dock refresh|apps` (built-in ids route to the clone).

Hyprland bindings (`~/.config/hypr/bindings.lua`):
- `SUPER + SUPER_L` -> `omarchy-shell mushroom-dock peek`
- `SUPER + A` -> `omarchy-shell mushroom-dock cycle 1`

A cloned plugin gets a scoped shell API without `shellConfig` or `appLibrary`,
so the dock reads and watches `~/.config/omarchy/shell.json` plus the packaged
defaults directly, and carries its own app-list, launch, icon, and uninstall
fallbacks (`uwsm-app -- gtk-launch`, `omarchy-launch-tui` for terminal entries).
All config writes still go through `omarchy-dock`.

### `omarchy/hooks/`
Custom hooks plus locally edited samples:
- `post-update.d/install-voxtype.hook`: offer Voxtype dictation install.
- `post-update.d/setup-agent.hook`: offer default agent setup when unset.
- `post-update.d/setup-fingerprint.hook`: offer fingerprint setup on capable hardware.
- `theme-set.d/10-owe-sync`: ping the `owe` daemon socket to refresh on theme change.

### `omarchy/branding/`, `omarchy/defaults/`, `omarchy/extensions/`
- `branding/about.txt`, `branding/screensaver.txt`: custom about/screensaver text.
- `defaults/agent` (`omp`), `defaults/dictation` (`voxtype`): chosen defaults.
  `omp` is what `SUPER + grave` (quake console) and `omarchy agent` launch.
- `extensions/omarchy-menu.jsonc`: launcher/menu extension file.

### Restore

```bash
rsync -a omarchy/ ~/.config/omarchy/
rsync -a hypr/ ~/.config/hypr/
mkdir -p ~/.local/bin
install -m755 bin/omarchy-space-double bin/omarchy-window-picker ~/.local/bin/
omarchy theme set mushroom-grove
omarchy restart shell
```

- `~/.local/state/omarchy/current/` is generated state and is not tracked.
  `omarchy theme set mushroom-grove` recreates it: the wallpaper symlink and the
  app theme files (`alacritty.toml`, `btop.theme`, `chromium.theme`, `foot.ini`,
  `ghostty.conf`, `fcitx5-theme.conf`, …).
- `omarchy/shell.json` already disables the built-in `omarchy.dock` and enables
  the vendored `mushroom.dock` clone, so the restored dock is the themed one.
- `hyprctl reload` picks up `~/.config/hypr` changes without restarting the
  session.
- `bin/` scripts must stay on `PATH` via `~/.local/bin`, which the Omarchy
  session already includes.

Third-party webcam plugin is not vendored; re-clone it before restarting:

```bash
git clone https://github.com/kristoferlund/omarchy-webcam.git \
  ~/.config/omarchy/plugins/io.github.kristoferlund.webcam
```

Dock pins are app ids from `shell.json` (`chromium`, `wezterm`, `Nautilus`,
`obsidian`, `signal`, `Discord`, `OBS`, `kdenlive`, `mpv`, `Moonlight`). Missing
apps restore as missing discs; install them to match the bar/dock exactly.

## Hyprland config

Mirror of `~/.config/hypr` (timestamped `.bak.*` backups excluded). Loaded by
`hyprland.lua` after Omarchy's defaults, so these files win over both the
defaults and the theme's `hyprland.lua`.

### `hypr/looknfeel.lua`
Sharp corners with tight outer margins: `decoration.rounding = 0` and
`gaps_out = { top = 10, right = 0, bottom = 4, left = 0 }`. This overrides the
theme's `rounding = 10`, so the live desktop has square window corners even
though `themes/mushroom-grove/hyprland.lua` sets rounding.

### `hypr/bindings.lua`
- `SUPER + J`: consume/expel a column in the scrolling layout, `togglesplit` in dwindle.
- `SUPER + mouse_down`/`mouse_up`: scroll the scrolling-layout strip (defaults unbound).
- `SUPER + SUPER_L`: peek `mushroom.dock`; `SUPER + A`: cycle dock apps.
- `SUPER + SPACE`: `omarchy-space-double` — tap opens the Omarchy menu, double tap
  opens `omarchy-window-picker`.
- `SUPER + H`: toggle `mushroom.dashboard`.
- `SUPER + CTRL + X`, `F9`: dictation, bound only when dictation is installed.

### `hypr/input.lua`
Natural two-finger scrolling; three-finger horizontal `SUPER` gesture scrolls the
window strip; `move_snap_to_grid`/`move_snap_cursor` snap each gesture to the
nearest column and move focus to it.

### `hypr/autostart.lua`
Focuses the `home` workspace shortly after login, which shows the dashboard.

### `hypr/monitors.lua`
`GDK_SCALE=2` and the preferred mode at scale `1.6`. Machine-specific — adjust
for other displays.

### `hypr/xdph.conf`, `hypr/hyprsunset.conf`
Screencopy uses `hyprland-preview-share-picker`; hyprsunset starts with an
identity profile at 07:00 (automatic nightlight is commented out).

## Scripts

### `bin/omarchy-space-double`
First tap runs `omarchy-menu toggle root`; a second tap within 400 ms
(`OMARCHY_DOUBLE_TAP_MS`) closes the menu and runs `omarchy-window-picker`.
`OMARCHY_SPACE_DRY=1` prints `menu`/`picker` instead of executing.

### `bin/omarchy-window-picker`
Lists mapped windows on regular workspaces via `hyprctl clients`, most recently
focused first, and matches `<title> · <class> · workspace <name>` with `fuzzel`.
Colors come from the active theme's `colors.toml`; `--print` dumps the rows.
Needs `jq`, `fuzzel`, and Hyprland.

### `scripts/bootstrap-ansible-child-node.sh`
General-purpose Linux bootstrap for Ansible-managed child nodes (not Vagrant-specific):
- Must run as `root`.
- Creates an `ansible` user/group by default (configurable).
- Installs base packages on apt systems (`sudo`, `python3`) unless disabled.
- Adds a supplied public key to `authorized_keys`.
- Configures sudo policy for the account.

Usage:

```bash
cd scripts
sudo ANSIBLE_PUBLIC_KEY_FILE=/path/to/ansible.pub ./bootstrap-ansible-child-node.sh
```

Or provide the key inline:

```bash
cd scripts
sudo ANSIBLE_PUBLIC_KEY='ssh-ed25519 AAAA... ansible@controller' ./bootstrap-ansible-child-node.sh
```

Optional environment overrides:
- `ANSIBLE_USER` (default `ansible`)
- `ANSIBLE_GROUP` (default same as user)
- `ANSIBLE_PASSWORDLESS_SUDO` (`true`/`false`, default `true`)
- `INSTALL_BASE_PACKAGES` (`true`/`false`, default `true`)

### `scripts/setup-wsl-ubuntu.sh`
Provision Ubuntu WSL with the same core dev toolchain as the Vagrant devbox:
- Installs core build/dev packages.
- Installs `uv` and a managed Python for the invoking user.
- Installs `nvm`, latest Node.js, and OpenAI Codex CLI for the invoking user.
- Installs latest stable Go and Neovim system-wide.

Usage:

```bash
cd scripts
sudo ./setup-wsl-ubuntu.sh
```

## Notes

- `vagrant/` is an active Ubuntu 24.04 automation setup:
  - Multi-machine support:
    - `devbox` (primary Ubuntu box)
    - `kali` (Kali rolling box)
    - `tails` (enabled only when `VAGRANT_TAILS_BOX` is set)
  - Launch commands:
    - `vagrant up devbox`
    - `vagrant up kali`
    - `VAGRANT_TAILS_BOX=<box-name> vagrant up tails`
  - Default network mode is bridged LAN static IP (`public_static`).
  - Default LAN static IPs:
    - `devbox`: `192.168.2.150`
    - `kali`: `192.168.2.151`
    - `tails`: `192.168.2.152`
  - Set `VAGRANT_NETWORK_MODE=private_static` to use host-only static IP (`192.168.56.x`) instead.
  - Set `VAGRANT_PRIVATE_IP` to override the host-only static IP.
  - Additional static IP overrides:
    - `VAGRANT_PRIVATE_IP_KALI` (default `192.168.56.11`)
    - `VAGRANT_PRIVATE_IP_TAILS` (default `192.168.56.12`)
  - Set `VAGRANT_NETWORK_MODE=private_dhcp` for host-only DHCP.
  - Set `VAGRANT_NETWORK_MODE=public` for bridged LAN DHCP.
  - Set `VAGRANT_NETWORK_MODE=public_static` for bridged LAN static IP (default).
  - Set `VAGRANT_BRIDGE_INTERFACE` to force a specific host NIC and avoid bridge prompts.
  - Per-machine bridge override:
    - `VAGRANT_BRIDGE_INTERFACE_DEVBOX`
    - `VAGRANT_BRIDGE_INTERFACE_KALI`
    - `VAGRANT_BRIDGE_INTERFACE_TAILS`
  - Static LAN IP vars for `public_static`:
    - `VAGRANT_PUBLIC_IP` (global override) or machine-specific `VAGRANT_PUBLIC_IP_DEVBOX`, `..._KALI`, `..._TAILS`
    - `VAGRANT_PUBLIC_NETMASK` (default `255.255.255.0`, machine-specific overrides also supported)
  - SSH forwarded port is configurable with `VAGRANT_SSH_PORT` and `VAGRANT_SSH_BIND_IP`.
  - Additional SSH port overrides:
    - `VAGRANT_SSH_PORT_KALI` (default `2223`)
    - `VAGRANT_SSH_PORT_TAILS` (default `2224`)
  - Box overrides:
    - `VAGRANT_DEVBOX_BOX` (default `bento/ubuntu-24.04`)
    - `VAGRANT_KALI_BOX` (default `kalilinux/rolling`)
    - `VAGRANT_TAILS_BOX` (required to enable `tails`)
  - In WSL, SSH host defaults to the WSL gateway; override with `VAGRANT_SSH_HOST` if needed.
  - In WSL, SSH key insertion defaults to off to avoid chmod failures on `/mnt/c`; override with `VAGRANT_SSH_INSERT_KEY=true`.
  - Set `VAGRANT_SSH_PRIVATE_KEY_PATH` to a Linux-filesystem key path if strict key permissions fail in WSL.
  - If `~/.vagrant-wsl-private-key` exists in WSL, it is used automatically.
  - Boot timeout override: `VAGRANT_BOOT_TIMEOUT` (seconds).
  - GUI is off by default for automation; set `VAGRANT_GUI=true` to enable it.
  - Resource overrides: `VAGRANT_MEMORY`, `VAGRANT_CPUS`.
  - Disk resize is opt-in: set `VAGRANT_ENABLE_DISKSIZE=true` (requires `vagrant-disksize`).
  - Bootstrap provisions development toolchains:
    - `uv` plus latest managed Python for `vagrant` and `dev` users.
    - `nvm` plus latest Node.js for `vagrant` and `dev` users.
    - OpenAI Codex CLI (`@openai/codex`) for `vagrant` and `dev` users.
    - Latest stable Go from `go.dev` archive.
    - Latest stable Neovim from official GitHub release tarballs.
    - GCC/Make toolchain from Ubuntu packages (`gcc`, `g++`, `make`, `build-essential`).
    - `ripgrep` (`rg`) from distro packages.
    - `ansible` from distro packages (when available).
  - Creates a `dev` user with password `dev` (for local VM access).
  - Adds `dev` to the `sudo` group.
  - Mounts repo `neovim/` into the VM and syncs it to `/home/dev/.config/nvim` during bootstrap.
  - Syncs discovered public keys on the VM into `vagrant` and `dev` `authorized_keys`.
  - `vagrant ssh <machine>` defaults to `dev` for already-created machines; first boot/provision still uses `vagrant`.
- This repo mixes Linux shell, Windows PowerShell/WezTerm, and Neovim config in one place.

## SSH to Devbox

- Preferred client: **MobaXterm**.
- VM credentials:
  - `dev` / `dev`
  - `vagrant` / `vagrant` (key-based SSH is the default with Vagrant)

### MobaXterm (Preferred)

1. Start `devbox`: `cd vagrant && vagrant up devbox`
2. Get SSH details: `vagrant ssh-config devbox`
3. In MobaXterm, create a new SSH session:
   - Remote host: value from `HostName` (usually `127.0.0.1` or WSL gateway)
   - Port: value from `Port` (default `2222`)
   - Username: `dev` (or `vagrant`)
   - Private key: use the identity file from `IdentityFile` if using key auth
4. Connect.

### CLI SSH

Use Vagrant directly:

```bash
cd vagrant
vagrant ssh devbox
```

Or use raw SSH with Vagrant-generated config:

```bash
cd vagrant
vagrant ssh-config devbox > /tmp/devbox-ssh.conf
ssh -F /tmp/devbox-ssh.conf default
```

## Dev Environment Setup

### Prerequisites

- Windows + WSL2
- VirtualBox
- Vagrant
- Enough resources (default VM profile): 8GB RAM, 4 CPUs, ~60GB free disk

### Quick start

Create a local Vagrant environment file and load it:

```bash
cd vagrant
cp .env.example .env
set -a; source .env; set +a
```

Then boot and connect:

```bash
cd vagrant
vagrant up devbox
vagrant ssh devbox
```

### LAN networking customization

Default behavior puts `devbox` on your LAN with static IP `192.168.2.150`. To force a specific NIC:

```bash
cd vagrant
set -a; source .env; set +a
VAGRANT_BRIDGE_INTERFACE="Realtek Gaming 2.5GbE Family Controller" \
vagrant reload devbox --provision
```

Use a different fixed LAN IP in that subnet:

```bash
cd vagrant
set -a; source .env; set +a
VAGRANT_BRIDGE_INTERFACE="Realtek Gaming 2.5GbE Family Controller" \
VAGRANT_PUBLIC_IP_DEVBOX=192.168.2.50 \
VAGRANT_PUBLIC_NETMASK=255.255.255.0 \
vagrant reload devbox --provision
```

Notes:
- `public` and `public_static` attach the VM directly to your LAN.
- For `public_static`, pick an unused IP in your LAN range and outside DHCP reservations/scopes.

Other machines:

```bash
cd vagrant
vagrant up kali
VAGRANT_TAILS_BOX=<box-name> vagrant up tails
```
